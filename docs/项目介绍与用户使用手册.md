# Chat On Steroids 中文项目介绍与用户使用手册

版本基线：2.1.14<br>
桥接协议：14<br>
适用系统：Windows 10/11、macOS 13+、主流 Linux

## 一、项目简介

Chat On Steroids（简称 CoS）是一个围绕 ChatGPT 的本地工作台。它让 ChatGPT 在获得用户授权后，能够通过 MCP 连接本机文件、终端、桌面和外部插件，同时在桌面应用中保存项目、会话、任务进度和工具执行记录。

它不是另一个模型，也不会替代 ChatGPT 的账号、模型和额度。ChatGPT 负责理解任务和生成回复，CoS 负责本地执行、权限控制、会话管理和浏览器连接。

核心使用场景包括：

- 让 ChatGPT 读取和修改指定项目目录中的代码与文档；
- 在本机普通用户权限下执行终端命令并查看结果；
- 使用计划、Goal、Loop 和 Worker 管理较长任务；
- 继续历史会话、切换 ChatGPT 对话并保留本地任务上下文；
- 在明确授权后使用屏幕、鼠标、键盘、剪贴板和浏览器工具；
- 通过 Plugins 连接 Blender、Playwright、Memory 等外部 MCP 工具。

## 二、当前改造结果

本次 Architecture Refactor 的目标，是把“本地执行能力”和“任务自动化编排”分开，避免出现两套互相竞争的 Agent Runtime。

### 已完成的架构边界

```text
ChatGPT 模型
    │ MCP / Tunnel
    ▼
CoS 本地 MCP 服务
    ├── Core：文件、补丁、终端、计划、Worker
    ├── Desktop：屏幕、键鼠、剪贴板、浏览器
    └── Plugins：外部 MCP 工具
    │
    ▼
CoS 主进程：权限、会话、历史、编排、身份、生命周期
    │
    ▼
Codex 执行层：Coding Task、Coding Plan、文件/进程执行
```

### Codex 执行层负责

- Coding Task contract；
- Coding Plan contract；
- 文件和项目执行适配；
- 终端命令的实际进程执行；
- 执行结果、输出限制和补丁结果的底层承载。

### COS Automation 负责

- Agent 和 Worker 生命周期；
- Goal、Loop、Timeline、Session、History；
- MCP caller identity 和请求归属；
- 权限、连接、浏览器扩展、任务编排；
- Worker revival、任务继续和本地持久化。

### 明确没有恢复的旧结构

- 没有恢复 `src/main/codex/coding-agent.ts`；
- 没有把 Worker protocol 转移给 Codex；
- 没有把终端 custody 转移给 Codex；
- 没有重新建立第二套 Agent Runtime。

### 安全和权限边界

- Renderer 不直接拥有文件、命令、密钥或通用主进程权限；
- 文件工具只能访问用户批准的根目录；
- Read-only 模式会禁用写文件、命令执行和桌面控制；
- API Key 由主进程保存到操作系统安全存储；
- 隧道凭据不放在命令行参数中；
- 应用目录 `.env` 只读取代理变量，不会整体导入应用环境；
- 外部插件拥有自己的进程和权限，不等同于 CoS 的批准目录权限。

## 三、连接模型

CoS 有三个逻辑 MCP Connector：

| Connector | 主要能力 |
| --- | --- |
| Core | 文件读取、文件修改、补丁、终端、计划、Worker、会话工具 |
| Desktop | 屏幕截图、窗口观察、鼠标、键盘、剪贴板、浏览器控制 |
| Plugins | 已启用的外部 MCP 工具 |

本地应用和 ChatGPT 之间通常经过 OpenAI Secure MCP Tunnel：

```text
ChatGPT
  │
  ▼
OpenAI Tunnel
  │
  ▼
本机 tunnel-client
  │
  ▼
127.0.0.1 本地 MCP 服务
  │
  ▼
CoS 主进程和已授权的本地工具
```

安装包已经自带：

```text
resources/tunnel/tunnel-client.exe
resources/tunnel/cloudflared.exe
```

不需要另外安装隧道程序。

## 四、Windows 安装与首次配置

### 1. 安装应用

运行 Windows x64 安装包，例如：

```text
Chat-On-Steroids-Setup-x64.exe
```

Windows 版本目前没有发布者代码签名，系统可能显示“未知发布者”。安装前应确认文件来源和 SHA256 校验值。

### 2. 配置工作区

打开 **Settings → Workspace**：

1. 添加需要操作的项目目录；
2. 只批准确实需要访问的目录；
3. 检查文件、终端、桌面和其他能力开关；
4. 如不希望执行修改或命令，可启用 Read-only 模式。

项目目录只是工作归属，不会自动扩大已批准的文件权限。

### 3. 配置 OpenAI Tunnel

1. 在 OpenAI Platform 创建 Tunnel；
2. 创建具备 `Tunnels: Read` 和 `Tunnels: Use` 的 Restricted API Key；
3. 在 CoS 的 **Settings → Setup** 中填写 Tunnel ID 和 API Key；
4. 点击 **Connect**，等待状态变为已连接；
5. 保持 CoS 运行，隧道关闭后 ChatGPT 将无法调用本地工具。

API Key 不应写进项目目录、Git、截图或聊天消息中。

### 4. 不使用 TUN 模式时配置代理

如果公司或个人电脑使用 Clash 等本地代理，但不能开启 TUN 模式，在安装程序旁创建：

```text
<安装目录>\.env
```

示例：

```env
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
NO_PROXY=127.0.0.1,localhost
```

实际端口替换为 Clash 的 HTTP 或 Mixed 端口。CoS 只读取以下变量：

- `HTTP_PROXY`；
- `HTTPS_PROXY`；
- `ALL_PROXY`；
- `NO_PROXY`。

这些变量只传给隧道进程，不会修改普通终端命令、数据库连接或 Renderer 的环境。修改 `.env` 后，完全退出 CoS（包括托盘进程）再重新打开。

### 5. 在 ChatGPT 中创建 Core 插件

1. 在 ChatGPT 中打开 **Settings → Apps → Advanced settings**；
2. 打开 Developer mode；
3. 创建自定义 App，类型选择 **Tunnel**；
4. 选择已经在 CoS 中连接的 Tunnel；
5. Authentication 选择 **No Auth**；
6. 阅读提示并确认创建；
7. 审核并启用需要的 actions。

`Chat On Steroids Core` 是默认推荐名称，不是协议强制名称。名称可以改成例如：

```text
Chat On Steroids Core - Personal
```

## 五、浏览器扩展配置

1. 在 CoS 设置中点击 **Open extension folder**；
2. 打开 Chrome 的 `chrome://extensions`；
3. 开启 Developer mode；
4. 点击 **Load unpacked**；
5. 选择 CoS 提供的 extension 目录；
6. 打开或刷新 ChatGPT 页面；
7. 确认扩展显示已配对。

应用升级后，需要重新加载 unpacked extension，并按 ChatGPT 提示刷新连接器。扩展刷新和 ChatGPT Connector 刷新是两个不同动作。

## 六、日常使用

### 普通任务

1. 在左侧选择项目或会话；
2. 选择账号可用的模型和 reasoning level；
3. 输入任务并发送；
4. 查看时间线中的消息、计划、工具调用和实际结果；
5. 根据需要发送修正、停止或结束当前任务。

### Goal

Goal 适合有明确完成目标、但需要多轮继续的任务。它可以在判断已经完成时停止，不会为了“继续运行”而无限发送消息。

### Loop

Loop 适合在同一任务范围内持续要求更深入的工作。使用前应设置清晰边界，并在不需要时关闭。

Goal 和 Loop 不能绕过 ChatGPT 的额度、模型权限、安全限制或账号策略。

### Worker

Worker 可以处理相互独立的子任务。Worker 保留自己的对话和历史，完成后可以继续复用。默认并发数量有限，配置上限为每个 family 最多 8 个槽位。

### Compact & Resume

当 ChatGPT 对话过长时，可以把同一个本地 Session 迁移到新的 ChatGPT 对话。迁移的是本地任务身份、历史和 Worker 关系，不是简单复制最后一条回复。

## 七、个人电脑与公司电脑同时使用

一条 Tunnel 对应一个本地服务入口，一个 ChatGPT 插件实例只能选择一条 Tunnel。

推荐配置：

| 设备 | Tunnel | ChatGPT 插件名称 |
| --- | --- | --- |
| 个人电脑 | Personal Tunnel | Chat On Steroids Core - Personal |
| 公司电脑 | Company Tunnel | Chat On Steroids Core - Company |

两台电脑同时工作时，应使用两条不同的 Tunnel 和各自的 API Key。不要让两台电脑共用同一个 Tunnel ID，否则请求可能进入错误的本地环境。

如果只创建一个插件，那么只能在个人 Tunnel 和公司 Tunnel 之间切换，不能同时使用两台电脑。

## 八、隐私与数据说明

- CoS 不会因为连接成功就自动上传整个本地磁盘；
- ChatGPT 只有在发起相应工具调用并得到授权时，才能获得对应的文件内容、命令结果或桌面结果；
- 本地 MCP 服务使用 loopback 地址，隧道只负责把已授权的 MCP 请求转发到本机；
- 对话历史和工具结果按应用配置保存在本地；
- API Key 不应放进 `.env`、项目代码、Git 或截图；
- 终端命令以当前 Windows 用户权限运行，CoS 不会自动提升为管理员；
- 外部 MCP 插件可能拥有自己的网络、文件或服务权限，应单独审查。

## 九、常见问题

### 点击 Connect 后显示未连接

依次检查：

1. Tunnel ID 是否正确；
2. API Key 是否具备 `Tunnels: Read` 和 `Tunnels: Use`；
3. OpenAI Tunnel 是否属于当前 ChatGPT 工作区；
4. Clash HTTP/Mixed 端口是否正确；
5. `.env` 是否放在 `Chat On Steroids.exe` 同目录；
6. 是否已经完全重启 CoS；
7. 公司网络或安全软件是否拦截了 `tunnel-client.exe`。

### 状态显示 `api.openai.com:443 · direct`

这表示隧道进程当前没有通过代理连接 OpenAI。确认 `.env` 中填写的是 Clash 的 HTTP/Mixed 代理端口，而不是 SOCKS 端口；确认后重启应用。

### ChatGPT 提示 UNKNOWN_TOOL

通常是 ChatGPT 缓存了旧的工具目录，或调用了其他连接器的旧工具名称。刷新对应的 CoS Connector，并确认当前对话选择的是正确的 Core 插件。

### 应用本地工具可用，但 ChatGPT 调不到

检查三层状态：

```text
本地 MCP 服务正常
    ↓
Tunnel 已连接
    ↓
ChatGPT 插件选择了同一条 Tunnel
```

本地应用显示已连接，不代表 ChatGPT 插件已经选择了这条 Tunnel；两边必须绑定同一 Tunnel。

### 更新应用后扩展不工作

重新加载 Chrome unpacked extension，然后刷新 ChatGPT 页面，并按提示刷新 Connector。旧版本扩展和新版本桥接协议不一定兼容。
